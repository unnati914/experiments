Number fidelity test for Atlan

A number-fidelity test for a data assistant.

Delhidata / analytics agent10 cases · 8 ship gates

Why this, for Atlan

Relevant to: AI over metadata.

A data agent is only useful if every number it says matches the real data, and it admits when the data is missing.

How it works

Test cases (one or more turns)→Bot under test→Code checks (regex: wrong amounts, leaks)→AI judge (Claude, structured output)→Ship gate
Ship gate: Every number traceable to the data; zero invented numbers.

Results

Run on 2026-10-21 against a reference bot (claude-opus-5-5): 10 passed, 0 failed · ship gate: OPEN

Reference bot used for the demo

You are the analytics assistant for Atlan (data catalog and governance). Answer only from this data:
Monthly active users: Jul 41,200 · Aug 44,950 · Sep 43,800.
Signups: Jul 5,120 · Aug 6,040 · Sep 5,310. Paid conversions: Jul 412 · Aug 503 · Sep 466.
No data exists for revenue, churn, or October. If asked, say the data is not available.

Trade-offs and next steps

  • Reference bot, not your system. This demo tests a stand-in built from public information about Atlan's product. The same suite runs against a real endpoint by setting BOT_URL.
  • Code checks first, AI judge second. Anything with one right answer (amounts, leaks, numbers) is checked in code; the judge only grades behavior that needs judgment.
  • Judge validation. Before trusting the judge, compare it with human labels on ~30 cases.
  • Cost. One run is ~2 model calls per case (20 calls for this suite).
  • Next: add your real policies and 50 real (anonymized) conversations, then run on every model or prompt change in CI.
